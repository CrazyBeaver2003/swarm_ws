# Роевое управление самолётными БПЛА

Симуляция **3–5 самолётов** с позиционированием от трёх наземных станций и
управлением «лидер–ведомые». Реализованы последовательный взлёт, линия и клин,
изменение интервалов и высоты, команды оператора лидеру и миссия к точке на карте.
Модель — **`rc_cessna`**, завершение миссии — **Hold: полёт по кругу ожидания**.

## Запуск

Стек: **Ubuntu 24.04 · ROS 2 Jazzy · Gazebo Harmonic · PX4 SITL 1.17 · C++/Python**.
Связь с PX4 — uXRCE-DDS и `px4-ros2-interface-lib`; MAVLink используется для
связи с наземной станцией. QGroundControl доступен для наблюдения и диагностики.

Перед первой сборкой нужны ROS/Gazebo, исходники `px4_msgs` и
`px4-ros2-interface-lib`, собранный PX4 и Micro XRCE-DDS Agent 2.4.3.
Пути стенда по умолчанию:

- PX4: `~/swarm_ws/third_party/PX4-Autopilot`;
- Agent: `~/.local/opt/micro-xrce-dds-agent-2.4.3/bin/MicroXRCEAgent`.

PX4 использует сохранённые [патчи магнитометра](patches/README.md).
`third_party/` не входит в Git. Совместимые ревизии:
PX4 `d6f12ad1c4f70ad3230afd7d86e971421e02fef4`,
px4_msgs `86d8239e962f6939e05c3737784f60c02fa884db`,
px4-ros2-interface-lib `4a3370f084ac6f1ef001a4afa2b007845ffd0837`.

```bash
cd ~/swarm_ws
source /opt/ros/jazzy/setup.bash
rosdep install --from-paths src --ignore-src --rosdistro jazzy -r -y
colcon build --symlink-install --packages-up-to swarm_bringup
source install/setup.bash
export ROS_DOMAIN_ID=0
```

Запуск всего стенда одной командой:

```bash
ros2 launch swarm_bringup swarm_full.launch.py count:=3
```

Панель оператора: **http://127.0.0.1:8080** внутри машины с симуляцией.
`count:=5` запускает пять бортов; `gazebo_gui:=false` отключает окно Gazebo.
Полный launch уже включает симуляцию, управление и регистратор метрик.

Дождаться свежей телеметрии всех бортов и состояния **DISARMED / Hold**.
Для ручного сценария: **«Взлёт по очереди» → дождаться взлёта всех → «Включить строй»**.
Для миссии: выбрать цель на карте и нажать **«Начать миссию к выбранной точке»**.
Взлёт и сбор группы выполнятся автоматически. **«Hold для всей группы»** отменяет
миссию. Остановка стенда — `Ctrl+C` в терминале launch.

## Архитектура

```text
Виртуальные RTT + барометр → mesh_localization → MeshEstimate
                                                ├→ внешняя навигация PX4 / EKF2
                                                └→ mesh relay → лидер–ведомые
Панель → менеджер / планировщик → курс, высота, EAS → Swarm Control → PX4
Ground truth + оценки + цели + статусы → swarm_evaluation → JSON / CSV / PNG
```

| Пакет | Назначение |
|---|---|
| `swarm_interfaces` | Сообщения измерений, состояния и команд; сервисы |
| `mesh_localization` | RTT, вычисление координат, фильтр Калмана, covariance и качество |
| `swarm_simulation` | Gazebo bridge, внешняя навигация PX4, mesh relay, панель оператора |
| `swarm_px4_bridge` | Телеметрия, внешний режим управления, взлёт и Hold |
| `swarm_control` | Менеджер группы, формации, команды лидеру, планировщик миссии |
| `swarm_evaluation` | Пассивная запись наблюдений и расчёт метрик |
| `swarm_bringup` | Общие launch-файлы и конфигурации |

Карта — **ENU**: X — восток, Y — север, Z — вверх. Высота команд — **AMSL**,
курс — от севера: 0° север, 90° восток. В GUI используются градусы, в ROS-командах —
радианы. На границе PX4 координаты преобразуются в NED.

## Позиционирование и модель связи

Станции находятся в точках `(0,0,0)`, `(500,0,0)`, `(250,433.0127,0)` м ENU:
треугольник с базой около 500 м. Дальность вычисляется по двустороннему RTT:

```text
rtt_ns = 2·distance_m / c ·10⁹ + actual_delay_ns + noise_ns
range_m = c/2 ·(rtt_ns − calibrated_delay_ns)·10⁻⁹
c = 299792458 м/с
```

Ошибка RTT в 1 нс даёт около 0,15 м ошибки дальности. Интервал измеряется одними
часами: абсолютная синхронизация часов станций не требуется. Задержка ответа
компенсируется калибровочной поправкой; на известной дистанции её можно оценить
как среднее `rtt_ns − 2·distance_m/c·10⁹`. В базовой модели фактическая и
калибровочная задержки равны 100000 нс. Их несовпадение создаёт постоянное смещение.

Барометр задаёт высоту и устраняет неоднозначность трёх наземных дальностей.
Координаты вычисляются взвешенным методом наименьших квадратов, затем сглаживаются
линейным фильтром Калмана с состоянием `[x,y,z,vx,vy,vz]`. Публикуются координаты,
скорость, covariance, timestamp, качество и статус `VALID / DEGRADED / INVALID`.

По умолчанию: RTT 20 Гц, СКО шума 1 нс, доставка 40±10 мс, вероятность потери 2%,
СКО барометра 0,5 м. Обмен состояниями бортов моделируется отдельно: доставка
20±5 мс, потери 0,5%. Здесь «±» обозначает СКО случайной задержки, не жёсткий предел.
Задержка доставки пакета не прибавляется ко времени распространения радиосигнала.

Ground truth доступен только модели виртуальных датчиков и независимой оценке.
Локализация и управление не получают готовые истинные координаты. Ведомые получают
состояние лидера через mesh relay; параметры формации — через сервисы менеджера.
GPS fusion в PX4 отключён. Радиофизика, маршрутизация реальной сети и дрейф часов
не моделируются.

Конфигурации: [станции](src/swarm_bringup/config/stations.yaml),
[RTT](src/mesh_localization/config/ranging.yaml),
[локализация](src/mesh_localization/config/localization.yaml),
[обмен бортов](src/swarm_bringup/config/network.yaml).

## Управление и динамика самолёта

**Swarm Control — внешний режим PX4.** Собственная логика задаёт курс, AMSL-высоту
и эквивалентную воздушную скорость (EAS); стабилизацию выполняют контуры PX4.
Ведомые сопровождают смещения относительно курса лидера с учётом его движения.
Перестроение сглаживается, высотные эшелоны разделены на 35 м.

| Ограничение задания | Значение |
|---|---:|
| EAS | 10–19 м/с |
| Изменение скорости / высоты | до 1 м/с² / 1,5 м/с |
| Крен / минимальный радиус при ограничении курса | 25° / 120 м |
| Перемещение целевого места в строю | до 2 м/с |
| Интервал формации | 45–120 м |
| Порог сближения / горизонт прогноза | 20 м / 8 с |

Фактические скорость, крен и вертикальная скорость дополнительно проверяются по
ULog PX4. Наземная скорость не равна воздушной при наличии ветра.

Миссия использует **Dubins-маршрут** с радиусом 350 м. Рабочая высота лидера
выбирается из конфигурации — 70 м над общим origin, с запасом на эшелоны.
После взлёта и сбора маршрут перестраивается от текущей mesh-позиции.
Ведомые сопровождают лидера, собственные маршруты к цели не строят.
Успех — достижение цели и статус **`completed`** после подтверждённого Hold группы.

## Проверка сценариев и метрик

Каждый сценарий выполнять в новом запуске симуляции и сохранять отдельно.

| Сценарий / видео | Что показать |
|---|---|
| **1. Взлёт и формации** | Последовательный взлёт; сбор; линия и клин; изменение интервала, например 60→90 м; изменение высоты |
| **2. Ручное управление** | Команды оператора на разные курсы, скорости и высоты; набор/снижение; автоматическое сопровождение ведомыми |
| **3. Автоматическая миссия** | Выбор цели на карте; автоматический взлёт и сбор; расчёт и прохождение маршрута; достижение цели и Hold |

Для воспроизводимых прогонов предусмотрен `scripts/run_scenario.py`
с аргументами `formation`, `manual`, `mission`. Он работает с уже запущенным стендом.
На видео ручного сценария и выбора цели должны быть видны действия оператора.

**Замер установившегося строя:** в UI нажать **«Начать замер»** после сборки,
затем **«Завершить и сохранить»**. После статуса **«Отчёт готов»** появятся сводка
и путь к результатам. Начальный подлёт не входит в выбранный интервал.
Для оценки взлёта, перестроений и безопасности использовать также
**«Сохранить весь полёт»**. Исходный журнал сохраняется непрерывно.

Результаты: `results/<прогон>/measurements/<замер>/` — выбранный интервал;
`results/<прогон>/exports/<снимок>/` — отчёт всего полёта на момент сохранения.
В отчёте находятся `metrics.json`, CSV и SQLite; интервальный замер также строит PNG.
После остановки симуляции полный отчёт с графиками можно получить командой:

```bash
ros2 run swarm_evaluation evaluate /путь/к/каталогу_прогона --plots
```

| Требование ТЗ | Метрика в отчёте |
|---|---|
| Позиционирование каждого борта | `vehicles[id].localization_3d_m`: `rmse`, `p95` |
| Удержание формации | `vehicles[id].formation_relative_m`: `mean`, `max` |
| Дистанции и опасные сближения | `pairs[pair].airborne_samples.min`, `airborne_observed_close_episodes`; дополнительно `all_samples` |
| Маршрут, высота, время цели | `missions[id]`: `cross_track_m`, `altitude_error_m`, `reported_time_to_goal_s`, `gt_time_to_goal_s` |
| Частота и возраст координат | `position_update_rate_hz`, `measurement_age_s`, `estimate_delivery_delay_s` внутри `vehicles[id]` |
| Задержки и потери связи | `links.ranging_counter_sessions`, `links.network_counter_sessions` |

`null` означает отсутствие данных. Проверять число сравнений и покрытие интервала;
маршрутные метрики требуют полёта по миссии. Для интервального замера потери считаются
по разности снимков счётчиков внутри окна, с указанием фактического покрытия.
Время до цели отсчитывается от начала миссии, если достижение попало в окно замера.
В текущей версии допуски GT-проверки цели (30 м / 10 м по высоте) отличаются от
контроллера (радиус запроса / 5 м); два времени нужно интерпретировать раздельно.

**Устойчивость:** повторить тот же сценарий отдельно с повышенным шумом RTT
(`rtt_noise_std_ns=5.0`), потерями (`loss_probability=0.10`) и кратким отключением
дальностей (`drop_all_ranges=true`, затем обязательно `false`) у `/rtt_sensor`.
Зафиксировать длительность разрыва по SIM time; сравнить ошибки, доступность оценок,
дистанции и режимы с базовым прогоном. Пример изменения параметра:

```bash
ros2 param set /rtt_sensor rtt_noise_std_ns 5.0
```

## Ограничения, выводы и комплект сдачи

Стенд рассчитан на плоский мир без препятствий и ветра. Нет обхода рельефа,
реального радиоканала и аппаратной калибровки. Детектор сближений запрашивает
восстановление/Hold, но не гарантирует отсутствие столкновений при любых условиях.
Численные пределы RMSE и ошибки строя в ТЗ не заданы: качество обосновывается
результатами всех трёх сценариев и экспериментов с деградацией.

По пункту 8 ТЗ предоставить:

- **GitHub/GitLab:** исходники, launch/config и этот README.
- **Три видео:** взлёт/формации; ручное управление; автоматическая миссия — по таблице выше.
- **Краткий отчёт на 1–3 страницы:** архитектура и математика описаны здесь;
  дополнить фактическими метриками трёх сценариев, сравнением условий и выводами.
  Приложить JSON/CSV/графики и ссылки на журналы, указать версии и параметры прогонов.

**Статус сдачи:** итоговая таблица результатов трёх сценариев и ссылки на видео
в этот README пока не внесены. Полная полётная приёмка здесь не заявляется.
Следует отдельно подтвердить удержание строя, интервалы и завершение миссии.

Использованы ROS 2, Gazebo, PX4, `px4_msgs`, `px4-ros2-interface-lib`;
собственная логика разрабатывалась с помощью AI и сверкой с веткой `gpt_test`.
Численные результаты других версий не считаются результатами текущего стенда.
