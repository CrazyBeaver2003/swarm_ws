# swarm_px4_bridge

## Восстановление после тайм-аута команд

При отсутствии принятой команды в течение двух секунд `swarm_control_node`
фиксирует ошибку и сообщает её PX4. Возобновление публикации само по себе
не снимает ошибку.

Для сброса используется приватный сервис `~/reset_fault` типа
`std_srvs/srv/Trigger`. При стандартном запуске он доступен как
`/swarm_control/reset_fault`.

Сброс разрешается, когда:

- `Swarm Control` деактивирован;
- свежий статус PX4 подтверждает фактический Hold и пользовательское намерение Hold;
- PX4 не сообщает активный failsafe;
- доступны свежие валидные положение и горизонтальная скорость выше 1 м/с;
- получена свежая валидная команда с возрастающей временной меткой.

Это сценарий восстановления летящего самолёта в Hold. Невалидные, повторные
и просроченные команды не обновляют свежесть источника. Возраст команды
считается от её создания, с пределом две секунды.

Порядок проверки в симуляторе:

1. В QGroundControl явно выбрать Hold и дождаться деактивации `Swarm Control`.
2. Возобновить публикацию команд с частотой 10 Гц, оставив её работающей.
3. В терминале с окружением ROS 2 и workspace вызвать:

   ```bash
   ros2 service call /swarm_control/reset_fault std_srvs/srv/Trigger "{}"
   ```

4. При `success: true` дождаться обновления доступности режима в PX4 и вручную
   выбрать `Swarm Control`.

При `success: false` поле `message` объясняет невыполненное условие.
Сервис только снимает ошибку: самолёт остаётся в Hold, а команды, наблюдавшиеся
до новой активации, не становятся заданиями нового сеанса.

Издатель и нода управления должны использовать согласованные часы ROS.
Для текущего стенда используется `use_sim_time=false`.
